# Локальный клиент MCP через SSH

`adapter.py` — точная копия клиента текущей Windows-установки. Он хранит только локальный каталог 14 инструментов; токен Яндекс Музыки находится на сервере. На discovery (`initialize`, `tools/list` и другие списки) отвечает локально. На `tools/call` запускает один процесс SSH, отправляет один JSON-RPC запрос и ждёт завершения. Ошибки не вызывают автоматического повтора операции.

В собственной копии измените `SSH_COMMAND`:

- Путь к `ssh.exe` для своей ОС, либо доступную в `PATH` команду `ssh`.
- Путь к **своему** закрытому ключу. Сам ключ в плагин, репозиторий и ZIP не включается.
- Пользователя/host и путь серверного wrapper `yandex-music-mcp-once`.

Сохраните `BatchMode=yes`, `IdentitiesOnly=yes` и `StrictHostKeyChecking=yes`; заранее добавьте проверенный host key своего сервера в `known_hosts`. У SSH-пользователя должны быть права выполнить предусмотренный wrapper. Название ключа и адрес в исходном файле относятся к установке владельца и требуют замены.

Подключите к MCP-клиенту Python с аргументами `-B` и абсолютным путём к своей копии `adapter.py`. Файл `music_catalog.json` должен оставаться рядом. Например, после адаптации на Windows:

```json
{
  "command": "python",
  "args": ["-B", "C:/MCP/yandex-music/client/adapter.py"]
}
```

При изменении серверных инструментов обновите обе копии каталога. Сценарий `../export_catalog.py` импортирует серверную конфигурацию; запускайте его только в подготовленном окружении, а не как проверку пакета без аккаунта.
