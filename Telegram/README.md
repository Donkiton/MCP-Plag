# tg — личный Telegram в ChatGPT и Codex

`@tg` подключает ваши Telegram-аккаунты к собственному MCP-серверу. Можно читать переписки, искать сообщения и выполнять доступные действия через ChatGPT или Codex. Основой служит фиксированный снимок [mcp-telegram-cloud](https://github.com/mcp-telegram/mcp-telegram-cloud); исходники и лицензия сохранены в `server/`.

Рабочий адрес установки владельца: `https://tg-77-238-249-144.sslip.io/mcp`. Состояние развёртывания и проверок нужно сверять с квитанцией текущего запуска: наличие исходников или ZIP не доказывает успешную авторизацию в Telegram.

[Текущее состояние и оставшиеся проверки](STATUS.md): сервер развёрнут, первый вход владельца ещё не завершён из-за ограничения попыток на my.telegram.org.

Для веб-ChatGPT создана отдельная **личная App-backed регистрация tg** с App ID `asdk_app_6adde97bd2a88191986f132cf6d4c496` и plugin ID `plugin_asdk_app_6adde97bd2a88191986f132cf6d4c496`. В `plugin-app/` подготовлен её пакет версии **1.0.2**, содержащий только настоящую привязку и два синхронных манифеста. Исходное оформление App сохранено. `plugin/` версии **0.1.0** остаётся отдельным переносимым источником с инструкцией для самостоятельного/desktop-подключения сервера; он не подменяет личную веб-регистрацию владельца.

## Подключение

1. Установите приватный плагин **tg**, откройте его подключение и нажмите **«Подключить»**.
2. Пройдите QR-вход в браузере: на телефоне выберите нужный Telegram-аккаунт, откройте «Настройки → Устройства → Подключить устройство» и отсканируйте QR. Если Telegram запросит 2FA, введите пароль непосредственно на защищённой странице подключения.
3. Задайте понятное название первого аккаунта, например «Личный».
4. Для другого аккаунта используйте страницу аккаунтов или команду `telegram-accounts-add`, затем отдельный QR-вход. Аккаунты можно переименовывать через `telegram-accounts-rename`.

Пароли, коды входа, `api_hash` и строки сессий не передаются в чат. Если сервер ещё не настроен, владелец сначала открывает защищённую одноразовую страницу настройки и указывает собственные Telegram API ID и API hash из [my.telegram.org/apps](https://my.telegram.org/apps).

## Выбор отправителя

У каждого подключённого Telegram-аккаунта есть постоянный ID и собственное название. Вызов записи выбирает аккаунт явно через `account`, например `Рабочий`, либо через числовой `account_id`. Одновременно оба поля передавать нельзя.

Если аккаунтов несколько, отсутствие отправителя при записи должно приводить к выбору аккаунта, а не к отправке из первого попавшегося. `account="all"` предназначен для поддерживаемых инструментов чтения; результаты подписываются аккаунтом. `telegram-accounts-switch` — совместимая настройка конкретной MCP-сессии для чтения, она не должна переключать отправителя другого клиента.

Примеры: «Покажи непрочитанные по всем аккаунтам», «Найди переписку о машине в личном аккаунте», «Отправь этот текст Андрею из рабочего аккаунта». По просьбе «подготовь ответ» плагин готовит текст; для отправки нужен явный запрос.

Подключения ChatGPT и Codex имеют отдельные OAuth-разрешения. Отключение одного MCP-клиента, удаление привязки Telegram-аккаунта и завершение Telegram-сессии — разные действия. Перед удалением смотрите описание конкретной команды.

## Что входит в комплект

| Путь | Содержимое |
| --- | --- |
| `plugin/` | Переносимый плагин `tg`: манифест, MCP-соединение, инструкция и четыре явных файла иконок |
| `plugin-app/` | Личная App-backed регистрация: настоящий `.app.json` и сохранённые root/legacy manifests 1.0.2, без необязательного skill |
| `app-assets/` | Утверждённый мастер и PNG 64/128/256 для отдельной загрузки иконки зарегистрированного App |
| `server/` | Исходники сервера, тесты, кастомные ресурсы и инструкции развёртывания |
| `tools/` | Воспроизводимая упаковка и проверки архивов, PNG, путей и контрольных сумм |
| `ICON-COVERAGE.md` | Полная карта источников и визуальная приёмка иконок |
| [`CAPABILITIES.md`](CAPABILITIES.md) | Сопоставление возможностей cloud и chigwell, добавленные команды и оставшиеся различия |
| `provenance.json` | Версии, ссылки, лицензии и происхождение ресурсов |
| `releases/tg-app-1.0.2.zip` | App-only пакет для обновления именно личной веб-регистрации владельца |
| `releases/tg-0.1.0.zip` | Переносимый плагин для самостоятельного подключения сервера |
| `releases/tg-mcp-0.1.0.zip` | Серверные исходники без секретов, данных и зависимостей |

Базовый каталог cloud сохраняется и расширяется отдельными доработками. Это не арифметическая сумма каталогов cloud и chigwell: совпадающие команды объединяются, недостающие возможности переносятся отдельно. Нельзя считать любую функцию chigwell доступной, пока она не объявлена реальным MCP-сервером и не проверена.

## Иконки и регистрация App

Утверждён **круглый вариант A**, созданный через ImageGen. Основной файл для регистрации — `app-assets/tg-256.png` (4 443 байта). Варианты 128 и 64 также меньше 10 000 байт. Этот бюджет выбран по рабочему примеру Mail; он не объявляется универсальным ограничением всех ресурсов плагина.

Зарегистрированное приложение хранит собственную иконку отдельно от `plugin.json`. Для личного App утверждённый PNG 256×256, 4 443 байта уже загружен через форму регистрации. В тёмной теме визуально проверены большой знак на карточке плагина, значок установленного плагина в боковой панели и малый знак в строке приложения — везде круглый самолёт. Светлая тема карточки, выбор `@tg`/композер после OAuth и реальные страницы QR/2FA/аккаунтов ещё требуют проверки после входа владельца.

В переносимом `plugin/` значения `logo`, `logoDark`, `composerIcon`, `composerIconDark` явно ведут на кастомные файлы. Один цветной знак намеренно используется в обеих темах. В App-backed пакете весь полученный `interface`, включая `defaultPrompt: null`, сохранён без изменений.

При проверке версии 1.0.1 веб-интерфейс показывал добавленный необязательный skill розово-жёлтым generic-кубом, хотя поддерживаемые `icon_small`/`icon_large` были заданы кастомными PNG. Поэтому пакет 1.0.2 убирает этот лишний skill и его декларацию из личного App. MCP-подключение и инструменты сохраняются; инструкция остаётся в переносимом `plugin/`. Несуществующие параметры для обхода поведения UI не добавлялись.

В переносимом пакете используется MCP URL с OAuth DCR и отсутствует `.app.json`. В личном `plugin-app/` сохранён настоящий App binding и нет второго `mcp.json`: это предотвращает дублирование одного подключения. Для своего сервера создайте собственную регистрацию и получите её реальные идентификаторы; личный App ID владельца не создаёт вам отдельный экземпляр сервера.

## Самостоятельный запуск

Для своего экземпляра нужны отдельный HTTPS-адрес, Telegram API ID/hash, секреты OAuth/настройки и ключ шифрования сессий. В `server/` используется Bun; точные версии зависимостей задаются lock-файлом. На небольшом VPS запускайте отдельную службу на loopback за nginx; не собирайте полный публичный frontend на рабочем сервере.

Используйте конфигурацию и инструкцию из `server/deploy/` и текущий `.env.example`. Замените адрес в конфигурации сервера и `plugin/mcp.json` на свой. Настройте шифрование и закрытые права на каталог состояния; не сохраняйте ключ рядом с опубликованными исходниками. Проверьте HTTPS, OAuth discovery, доступность `/mcp` и только затем регистрируйте приложение с кастомной иконкой.

Вход в Telegram завершает владелец в браузере. После подключения отдельно проверьте чтение, выбранный аккаунт, отправку в «Избранное», перезапуск службы и повторный запрос. Для двух аккаунтов проверьте одновременные действия ChatGPT и Codex с разными отправителями.

## Сборка и проверки

Из корня репозитория:

```sh
python Telegram/tools/build_releases.py
python Telegram/tools/verify_package.py
python Telegram/tools/verify_app_source.py
```

Три архива создаются в `Telegram/releases/`. Упаковка использует фиксированные временные метки и проверяет состав; в серверный ZIP не входят `node_modules`, runtime-данные, `.env`, базы, логи и неиспользуемые frontend-workspaces `app/` и `web/`. Сборку повторяют после последнего изменения исходников.

`verify_app_source.py` сравнивает App-backed пакет с полученным релизом 1.0.1: имя, автор, описание, весь `interface`, `null` prompts и binding сохраняются; разрешены только версия 1.0.2 и удаление необязательного skill с его legacy-декларацией. В `plugin-app/` и его ZIP должны быть ровно три файла, без `skills/` и второго MCP-соединения. Отчёт — `tools/app-preservation-report.json`; он содержит точные четыре `delete_paths` для отдельного guarded update. Проверка не применяет правила создания нового portable listing к существующим App-owned значениям и не сокращает их.

В основном потоке разработки прошли **923 интеграционных и регрессионных теста** бэкенда. HTTPS-проверка ресурсов отдельно сравнивает фактические байты пяти серверных значков с утверждёнными файлами. Эти проверки не выполняют вход в Telegram и не доказывают работу реальных переписок до авторизации владельца.

Проверка файлов не заменяет визуальную приёмку. Для завершения задачи утверждённый знак должен отображаться на карточке App, карточке плагина, в боковой панели, выборе `@tg`, композере и на страницах подключения и аккаунтов в обеих темах. Неотображающийся или стандартный значок означает незавершённый слот.

## Данные и исходники

Сервер хранит действующие Telegram-сессии и участвует в обработке переписок. Результаты вызванных инструментов передаются клиенту ChatGPT/Codex. Секреты и пользовательские данные в публикуемый комплект не входят. После timeout записи нельзя автоматически повторять отправку: операция могла выполниться в Telegram.

MIT-лицензия upstream сохранена в `server/LICENSE`. Ссылки и фиксированные ревизии приведены в `provenance.json`. Если в дальнейшем переносится код из Apache-2.0 проекта chigwell, вместе с ним сохраняются обязательные уведомления и лицензия.
